# LT向けAIスライド生成アプリ 要件

最終更新: 2026-09-26

## 目的

AIとの対話を通じて、ライトニングトーク（LT）の目的・対象者・前提・構成を整理し、1資料1JSONの資料データを段階的に改善できるようにする。

AIは一度で完成品を出力するのではなく、人間からの追加指示を受けながら資料を更新する。

## 初期対象

- 技術系LT
- 5〜10分程度の発表
- 初心者〜中級者向けの技術共有
- 日本語資料
- 16:9のスライド

## 利用フロー

```text
ユーザーの依頼
  ↓
AIが目的・対象者・利用場面を質問
  ↓
AIが前提と構成を整理
  ↓
presentation.jsonを生成
  ↓
Marp用Markdownを生成
  ↓
HTML / PDF / PNGを出力
  ↓
ユーザーが確認
  ↓
追加指示でJSONを更新
```

## 実装対象

- AI向けの質問・生成手順をSkillとして定義する
- 資料全体を1つのJSONファイルで管理する
- JSON Schemaで構造を検証する
- ページテンプレートとデザインコンポーネントをJSONから指定する
- JSONからMarp用Markdownを生成する
- HTMLとしてブラウザで閲覧できるようにする
- PDF・PNGを出力できるようにする
- AIが新しいデザインコンポーネントを追加できる仕組みを用意する

## 初期実装の対象外

- ブラウザ上での直接編集
- アプリ内のFigma／PowerPoint編集UI
- PowerPoint出力の最適化
- Figmaへのネイティブオブジェクト出力
- 高度なアニメーション
- 複数テーマの同時提供

## LT向け初期ページテンプレート候補

- `cover-hero`: タイトルとビジュアルによる導入
- `message`: 主張を大きく提示
- `two-column`: 左右の説明・比較
- `process`: 手順・フロー・仕組み
- `closing`: まとめ・行動喚起

## 成功条件

- ユーザーの目的・対象者・前提をJSONに保持できる
- AIが既存コンポーネントを選択して資料を構成できる
- AIへの追加指示で特定スライドだけを更新できる
- JSONからHTMLを生成してブラウザで確認できる
- 文字切れやレイアウト崩れを検証できる
- 新しいデザインコンポーネントを既存資料へ追加できる
